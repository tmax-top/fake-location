### 现场证据（adb 抓取）

1. 系统通知（`dumpsys notification --noredact`）：
   - `key=0|android|11|GnssNotificationManager|1000`，`pkg=android`，channel `GPS_STATUS_MONITOR_ID`
   - 标题 `FakeLocation` / 正文 `正在提供模拟位置`，action「关闭模拟定位」→ `android/GnssService`
   - `timeout=PT72H`、`isNoisy=true`、`airtimeCount=21`（8 秒内 T0/T1 均为 21，说明是**每次状态变化时重弹**，非定时循环）
   - 结论：系统级通知，App 无法抑制
2. `dumpsys location` 历史日志出现成组三连：
   `10:00:09` / `10:04:13` / `10:04:21` / `10:04:30` 均为
   `gps removed mock override → added → removed`；`10:00:21` 还含 network 的 remove/add
   → 精确对应 `MockAuthChecker.isAuthorized()` 的「清理 → 探测 → 清理」副作用
3. `dumpsys location` 当前状态：
   - `network provider [mock]` 残留北京 mock 坐标 `39.905714,116.391297 ... mock`
   - **`gps provider: last location=null`** ← gps 通道已被探测删掉
   - `fused provider` = `31.238649,121.433987`，Bundle 带 `amap=1 / flpProvider=network`
     → 高德自有定位结果（上海真实位置）
4. `ps -A | grep fakelocation` 为空 → App 进程已被系统回收
5. `cmd appops get com.fakelocation android:mock_location` = `allow` → 授权本身正常，不是授权问题
6. `settings get secure mock_location_app` = `null`（该 ROM 用 AppOps 而非 secure setting 记录）

### 因果链

- `HomeRoute.kt:100` ON_RESUME → `refreshAuthState()` → `isAuthorized()` 每次 remove/add/remove
  → ① 每次 add 触发系统重弹通知；② 运行中删掉 gps test provider，注入只剩 network
- 切到高德 → 无前台服务 → 进程被回收 → 注入协程停止
- 高德走 AMap SDK / `fused` provider + `isFromMockProvider` 过滤 → 丢弃 mock，回落真实坐标
- 启动瞬间「闪一下」= 读到 last known mock 坐标，随后被自有融合定位覆盖

### 可修 / 不可修边界（已向用户说明）

| 项 | 结论 |
|----|------|
| 系统「正在提供模拟位置」通知 | **不可修**，AOSP/MIUI 强制，免 Root 无解 |
| 反复重弹（airtimeCount 累加） | **可修**：缓存授权态 + 运行中跳过探测 + 探针改用独立 provider 名 |
| gps 通道被误删 | **可修**：同上 |
| 切后台进程被杀、注入停止 | **可修**：前台 Service + 常驻通知 |
| 高德 AMap SDK / `isFromMockProvider` 反作弊 | **基本不可修**，免 Root 方案的固有上限 |
