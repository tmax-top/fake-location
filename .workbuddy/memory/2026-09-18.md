## 提交完整工程基线 + 修正 .gitignore

**仓库现状**：远端 `fake-location` → `git@github.com:tmax-top/fake-location.git`，分支 `master` 跟踪 `fake-location/master`。

**提交**：`8f67bd3` "chore: 导入 v0.2.0 完整工程基线，修正 .gitignore"（101 files changed, 4957 insertions）

**修掉的两个坑（重要，会复发）**：

1. **`.gitignore` 的 `build/` 规则缺少层级覆盖能力**
   - 原内容：`/build`、`*/build/`、`/app/build/`、`/*/build/`、`/build-logic/**/build/`
   - 问题：gitignore 中带 `/` 的模式锚定到根目录且 `*` 不跨 `/`，所以 `*/build/` 只匹配**一层**目录。`core/core-common/build/`、`feature/feature-home/build/` 是两层 → **完全没被忽略**
   - 后果：待提交文件数 **3581**，其中 3534 个是 dex/bin/class 构建产物
   - 修法：改用**不带前导斜杠**的 `build/`、`.gradle/`（匹配任意层级）
   - 修正后：待提交 **101** 个文件
   - 教训：Android 多模块工程一律用不带斜杠的 `build/`，不要写 `*/build/`

2. **全局 gitignore 会吞掉所有仓库的 `.gitignore`**
   - `~/.gitignore_global` 第 6 行有一条 `.gitignore`
   - 后果：任何仓库的 `.gitignore` 都不会出现在 `git status` 的 untracked 列表里，无法正常 `git add`
   - 本次处理：`git add -f .gitignore` 强制纳入跟踪
   - **待用户决定**：是否从 `~/.gitignore_global` 删除该行（影响其所有仓库，未擅自修改）

## 修复「地图空白 + 搜索不可用」—— 根因是 DNS 污染

**用户报障**：地图不能搜索、加载不出来、收到报错；并指出「地图瓦片可能是缓存，移到新位置就不显示」。

**排查过程（关键：用 adb 直连真机取证据）**：

1. 截图错误信息 → `failed to connect to nominatim.openstreetmap.org/199.16.156.39 (port 443) ... after 5000ms`，是**连接超时**不是 HTTP 错误
2. 真机复现：清 logcat → 启动 app → `adb shell input swipe` 拖拽地图 →
   ```
   OsmDroid: IOException downloading MapTile: /12/3429/1677
     java.net.ConnectException: Failed to connect to tile.openstreetmap.org/156.233.67.243:443
   ```
3. TCP 连通性对照实验（**决定性证据**）：
   - 直连正确 IP `146.75.45.91:443` → **TCP-OK**
   - 直连真机解析出的 `74.86.142.55` / `104.23.124.189` → **超时**
   - 对照组 baidu:443 → OK
   → **网络链路正常，纯 DNS 问题**
4. 多 DNS 对比：手机用路由器 `192.168.31.1` 得到污染结果；`114.114.114.114` 给出正确的 `146.75.45.91`；`223.5.5.5` / `8.8.8.8` 返回 **Facebook 的 IP 段**（`31.13.73.169` / `179.60.193.9`）—— 典型 GFW 污染特征

**修复（保持免 Key、保持 WGS-84）**：
- 新增 `feature-home/.../map/OsmTileSources.kt`：3 个 OSM 候选瓦片源（France HOT / Germany / 官方）+ 4s 超时探测 + 进程内缓存切换
- `HomeViewModel`：Nominatim 单源 → **Photon 主源 + Nominatim 兜底**，加 250ms 防抖，超时 5s→8s/10s，错误文案改可操作
- `HomeRoute`：`createMapView` 接受 tileSource 参数；补 `CopyrightOverlay`（ODbL 署名，此前缺失）

**踩到的坑**：Photon **只支持 `default/de/en/fr`，传 `lang=zh` 直接 HTTP 400**（错误响应里明说了）。
去掉 lang 参数即可 —— 不带时返回 OSM 原始名称，中国区数据本身就是中文。

**真机验证**：瓦片源探测成功切到 OSMFranceHOT，`IOException downloading MapTile` 失败数 **0**；
Photon 主源直接命中（降级次数 0），搜索返回 6 条中文结果，如
`上海站 · 上海火车站南广场 · 天目西路街道 · 静安区 · 上海市 · 中国`。

**可复用的排查手法**（写进 `docs/network-reachability.md` 第 3 节）：
> 判据：若 `ping` 出的 IP 直连不通、而直连已知正确 IP 通 → 是 DNS 问题，不是网络封锁。
> 常用命令：`adb shell ping -c1 <host>`、`adb shell "nc -w6 -z <ip> 443"`、`dig +short @<ns> <host>`、
> `adb logcat -d | grep -E "OsmTileSources|HomeViewModel"`

**注意**：`docs/network-reachability.md` 是本次新增的关键文档，记录了完整的实测数据与多源策略。
